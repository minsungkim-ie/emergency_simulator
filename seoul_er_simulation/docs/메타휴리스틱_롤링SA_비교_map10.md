# 롤링 SA(메타휴리스틱) 배정 vs 순차·전역 — 비교 실험 (2026-10-17, `seoul_er_dispatch_map_10.html`)

> 1차 실험(1~5장)에 이어 같은 날 2차 실험(6장: 단순 탐욕 대조군, 수요 세분화, 국지 폭주, 병상 반납 예측)과 팀 공유 메모(7장)를 추가했다.

9번 번들을 복사해 10번 파일을 만들고 **롤링 호라이즌 SA(담금질) 배정**과 **ETA 기준 전역 탐욕**을 추가해 같은 시드로 비교했다. 9번 파일과 저장소 원본(index.html, sim.js)은 건드리지 않았다. git 커밋은 하지 않았다.

## 1. 결론 (먼저)

1. **이송시간 개선의 대부분은 SA가 아니라 "직선거리 대신 도로 소요시간(ETA)을 쓴 것"에서 나온다.** 평시(×1) 평균 이송시간이 직선거리 기준 전역 스캔 18.7분 → ETA 기준 14.7분(−21%). SA를 얹어도 평균은 그대로(14.7분)다.
2. **SA가 ETA 탐욕보다 확실히 낫게 만든 것은 병원 쏠림이다.** 만석 병원 수(시간평균, 51곳 중)가 ×1에서 5.7 → 1.0, ×2에서 17.0 → 8.3으로 줄었다. 중증 환자 이송시간도 ×2에서 19.0 → 17.7분(시드 5/5 모두 개선).
3. **배정 실패는 수요 ×2.5 구간에서만 의미 있게 줄었다**(472 → 454명, −3.9%, 시드 5/5 개선). 수요 ×3처럼 완전 포화에서는 차이가 오차 범위다(−12 ± 10.6).
4. **(1차 결론, 2차에서 보완됨)** 요소별 제거 실험(×2.5)에서는 이득이 "혼잡 벌점"에서 나오고 가상 환자 예측과 SA 탐색은 거의 기여하지 않았다. 2차 실험에서 확인한 것: **"ETA + 혼잡 벌점"만 쓰는 단순 탐욕은 평시와 국지 폭주에서 SA와 사실상 같다**(이송시간 차이 0.1분 이내, 실패 차이 오차 범위). SA가 단순 탐욕보다 나은 구간은 **포화 경계(수요 ×2.4~2.6)** 뿐이고, 거기서 실패 −13~−19명(−8%, −2.6%), 이송 −0.5분이다. 이 이득은 주로 가상 환자 예측에서 나오는 것으로 보이나 ×2.5 제거 실험과 ×2.8에서는 보이지 않아 일관성은 약하다.
5. 순차 탐색 vs 전역 스캔은 평시에 탐색시간 차이 정도(이 실험은 10초 간격이라 순차 0.8분 vs 전역 0.17분 @×1)이고, 혼잡 시 순차가 오히려 실패가 적게 나왔다(아래 5장 주의).
6. **병상 반납 예측을 목적함수에 넣으면 오히려 나빠졌다**(평균 재실시간 4.2시간 가정): ×2.6에서 실패 +16명, 이송 +0.2분.
7. **직선거리 → ETA 전환은 기본 모드인 순차 탐색에서도 같은 크기의 효과**가 있다(평시 18.7 → 14.7분). 다만 ETA 하나만 쓰면 병원 쏠림이 커져 ×2에서 순차 탐색 실패가 3.6 → 11.6명으로 늘었다(7장).

## 3. 롤링 SA 설계

- **언제:** 대기 환자가 있는 매 틱마다 다시 푼다(롤링). 별도 대기 없이 발생 즉시 배정되므로 전역 스캔과 탐색시간이 같다.
- **무엇을 푸나:** 지금 대기 중인 실제 환자 + 앞으로 20분간 올 것으로 **예측한** 가상 환자(도착률 × 확률표 분포를 별도 난수열로 추출; 실제 미래 환자열은 보지 않음)를 한꺼번에 병원에 배정하는 문제. 실제 환자의 배정만 확정하고 가상 환자는 버린다.
- **목적함수(초 단위):** 중증도 가중 이송시간(중증 ×2, 응급 ×1, 경증 ×0.6; 가상 환자는 ×0.3) + 병원 응급실 가동률 80% 초과분의 제곱 벌점(최대 1200초 규모) + 가상 환자가 들어갈 병상이 없을 때 1800초 벌점.
- **제약(실제 환자):** 응급실 여유, ICU 종류별 여유, 수술실 여유, 진료계열 — `isHospitalEligible()`과 같은 조건. 확정 직전에 `isHospitalEligible()`로 한 번 더 확인한다.
- **SA:** 탐욕 초기해에서 출발, 이동(가까운 10곳 우선)과 교환 이웃, 온도 300→5초 기하 냉각, 반복 60×항목 수(300~4000). 호출당 평균 약 3~13ms.
- **정보 가정:** 병상 현황은 전역 스캔처럼 실시간으로 안다. 병상 반납 시점은 예측에 쓰지 않는다(현장에서 알 수 없으므로). 따라서 SA vs 전역은 "알고리즘"만의 차이다.

## 5. 해석할 때 주의할 점

- **대기열 처리 순서가 결과를 크게 바꾼다.** 처음에 SA를 기존 전역 스캔과 바로 비교했더니 혼잡할 때 SA 대기시간이 길고 실패도 많게 나왔는데, 원인은 알고리즘이 아니라 순서였다(기존 전역: 최근 환자부터, SA: 중증·오래 기다린 순). 그래서 ETA 탐욕과 SA는 같은 순서로 맞췄다. 기존 전역 스캔·순차 탐색은 원래 순서를 유지했으므로, **알고리즘 효과는 "전역(ETA) vs SA"로만 읽어야 한다.**
- **혼잡 구간의 총 실패 수는 중증 우선 정책의 대가를 포함한다.** 중증 우선(ETA 탐욕·SA)은 중증 환자 실패를 거의 0으로 만들지만, 재실이 긴 중증 환자가 병상을 차지해 총 처리량이 줄고 경증 실패가 늘어난다(중증도 가중을 끈 변형은 총 실패 313명이지만 중증 90명이 실패한다). 따라서 ×2.5·×3에서 순차·직선 전역이 총 실패가 적게 나온 것은 "더 낫다"가 아니라 정책이 다른 결과다.
- **×2.5·×3은 응급실이 거의 100% 찬 스트레스 시나리오**다(평시 ×1은 가동률 약 43%). 현실 예측이라기보다 "방식별로 어디서 무너지나"를 보는 조건이다.
- 이송시간은 캐시된 경로 소요시간 기준이고, 전역(직선)은 직선거리로 병원을 골라 실제 소요시간이 더 길어진다. 이 격차가 크게 나온 것은 직선거리 기준 선택이 도로 사정을 반영하지 못하기 때문으로 보인다(원인 분해는 하지 않음).
- 탐색시간은 고정 간격(10초) 때문에 최소 0.17분으로 나온다. 순차·ETA·SA 간 상대 비교용이다.
- SA 파라미터(가중치·온도·예측 구간)는 튜닝하지 않았다. 예측 구간이나 가상 환자 가중을 바꾸면 "미래 예측" 효과가 달라질 수 있다. 다만 반복 횟수를 크게 줄여도 같은 결과여서 탐색 능력보다는 목적함수 설계가 성능을 결정하는 구조로 보인다.
- 시드 5개·2일이라 ×2.5 이외 구간의 실패 차이는 통계적으로 약하다. 발표에 쓸 때는 시드를 늘리는 것이 좋다.

### 6-2. 국지 폭주 (평소 ×1 + 2시간 동안 한 지점 반경 2.5km에 추가 환자, 1일)

별도 난수열로 만든 추가 환자를 강남역(37.4979, 127.0276) 또는 종로(37.5704, 126.9921) 주변에 시작 후 1시간부터 2시간 동안 뿌린다. 시드가 같으면 모드와 무관하게 같은 폭주 환자열이다.

| | + 반납 예측 | 155.2 | 24.00 | 24.50 | 20.87 |

쌍별 차이는 실패 +2.6(×2.4, 시드 부호가 섞임), +15.6(×2.6, 5/5 악화), 이송 +0.2~+0.4분(×2.4 5/5, ×2.6 5/5 악화). **개선 없음, 약간 악화.** 병원별 평균 재실시간만으로는 반납 시점 정보가 부족해 "곧 비겠지"라는 낙관이 오히려 과밀 병원에 환자를 보내게 만든 것으로 보인다(원인 분해는 하지 않음). 실제 남은 재실시간을 알 수 없으므로(E-Gen은 가용 병상 수만 제공) 이 방향은 추가 투자 대비 기대가 낮다.

## 7. 팀 공유 메모 — `scoreHospital()`을 직선거리에서 ETA로

**한 줄 요약:** 병원을 고를 때 직선거리 대신 캐시된 도로 소요시간(ETA)을 쓰면 평균 이송시간이 약 4분(21%) 줄어든다. 기본 모드(순차 탐색)에서도 같다.

측정(같은 시드, 2일, 직선 → ETA):

| | 모드 | 평균 이송 (분) | 중증 이송 (분) | 실패 | 만석 병원 수 |
|---|---|---|---|---|---|
| 평시 ×1 (시드 3개) | 순차 탐색 | 18.71 → **14.67** | 19.03 → 15.12 | 0 → 0 | 3.60 → 5.76 |
| | 전역 즉시 | 18.71 → **14.66** | 19.06 → 15.16 | 0 → 0 | 3.55 → 5.76 |
| 혼잡 ×2 (시드 5개) | 순차 탐색 | 21.94 → **18.36** | 22.44 → 18.96 | 3.6 → **11.6** | 15.05 → 17.00 |
| | 전역 즉시 | 21.95 → **18.42** | 22.48 → 19.03 | 0 → 0 | 14.93 → 16.97 |

바꿀 곳(`scoreHospital`은 `selectHospital`과 `buildContactCandidates`가 모두 쓰므로 한 군데만 고치면 된다):

```js
// 현재: 직선거리
function scoreHospital(patient, hospital){
  return haversineMeters(patient.lat, patient.lng, hospital.lat, hospital.lng);
}

// 제안: 격자 대표점 → 병원 캐시 소요시간(초), 캐시에 없으면 직선 근사
function scoreHospital(patient, hospital){
  var hIdx = hospitals.indexOf(hospital);
  var oi = Number.isInteger(patient.routeOriginIdx) ? patient.routeOriginIdx : nearestOriginIdx(patient.lat, patient.lng);
  var c = ROUTE_CACHE[oi+'_'+hIdx];
  return c ? c.d
           : haversineMeters(patient.lat, patient.lng, hospital.lat, hospital.lng)/(AVG_SPEED_KMH*1000/3600)*1.05;
}
```

(10번 파일에는 `SCORE_BY_ETA` 스위치와 콘솔 `SIM_DEBUG.setScoreByEta(true)`로 이미 들어 있다.)

주의:
- **ETA만 쓰면 병원 쏠림이 늘어난다**(만석 병원 수 +2). 순차 탐색은 그래서 혼잡(×2)에서 거절이 늘어 실패가 3.6 → 11.6명이 됐다. 전역 방식은 영향이 없다. 순차 탐색에 ETA를 쓰려면 후보 정렬 점수에 혼잡 벌점을 같이 넣는 것이 안전해 보이나(전역 방식에서 "ETA + 혼잡 벌점"이 쏠림을 해소한 결과 근거), 순차 탐색에서의 그 조합은 측정하지 않았다.
- 이송시간은 원래도 캐시 소요시간을 쓰므로, 이 개선은 "선택 기준을 이송시간 계산과 맞춘 효과"다. 캐시 값이 실제 도로 사정을 반영한다는 가정에 의존하고, 출발점은 16개 격자 대표점이라 같은 격자 안 환자들은 같은 ETA 순서를 갖는다.
- 직선 대비 개선폭이 이만큼 큰 원인(직선 최단 병원과 도로 최단 병원이 자주 다르다)은 따로 분해하지 않았다.

## 8. 남은 일

- 순차 탐색에 "ETA + 혼잡 벌점" 후보 정렬을 적용해 쏠림 부작용 없이 이송시간 이득이 유지되는지 확인.
- 포화 경계(×2.4~2.6)에서 SA의 가상 환자 효과가 정말 있는지 시드를 늘려 재검증(지금은 구간별로 일관되지 않음). 예측 구간 길이, 가상 환자 가중, 벌점 가중 민감도.
- SA 대신 더 단순한 개선(예: 대기열 묶음 최적화만)이 포화 경계 이득을 설명하는지 확인.
